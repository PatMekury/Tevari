# YouVersion Bible API Notes

This document captures how Tevari integrates with the YouVersion Bible API and how it converts human-readable Bible references into the passage IDs used in the app.

## Repository context

- Repository: `PatMekury/Tevari`
- Primary backend implementation: `backend/functions/src/index.js`
- Swift client wrapper: `Tevari/TevariAPI.swift`
- Product docs: `README.md`

## High-level architecture

Tevari intentionally separates:

- Gloo AI content generation
- YouVersion licensed Scripture retrieval
- Story narration generated by the private Kokoro service

The product docs explicitly describe this boundary in `README.md`:

- Gloo generates prayer, reflections, scene guidance, and narration
- YouVersion provides the actual Bible text and attribution
- Tevari never stores its own generated Bible text as a local corpus

## How the YouVersion API is implemented

The main implementation lives in `backend/functions/src/index.js` in the function `licensedScripture(passageID)`.

```javascript
async function licensedScripture(passageID) {
  const headers = { "X-YVP-App-Key": youVersionAppKey.value(), Accept: "application/json" };
  const passageResponse = await fetch(
    `https://api.youversion.com/v1/bibles/${tevariBibleID}/passages/${encodeURIComponent(passageID)}?format=text&include_headings=false&include_notes=false`,
    { headers }
  );
  if (!passageResponse.ok) throw new Error(`YouVersion NIV11 passage failed with ${passageResponse.status}`);
  const passage = await passageResponse.json();
  if (typeof passage?.content !== "string" || typeof passage?.reference !== "string") {
    throw new Error("YouVersion returned an unusable passage.");
  }
  return {
    id: String(passage.id || passageID),
    reference: passage.reference,
    content: passage.content,
    bible: {
      id: tevariBibleID,
      title: "New International Version 2011",
      abbreviation: "NIV11",
      copyright: null,
      publisherURL: null,
      deepLink: null
    }
  };
}
```

### Important implementation details

- Secret name: `YVP_APP_KEY`
- Header used: `X-YVP-App-Key`
- Translation used: NIV11
- Bible ID constant:

```javascript
const tevariBibleID = 111; // New International Version 2011 (NIV11)
```

### API endpoint used

```text
https://api.youversion.com/v1/bibles/{bibleID}/passages/{passageID}?format=text&include_headings=false&include_notes=false
```

This is the exact pattern used for retrieving Scripture from YouVersion.

## How Bible codes are called

Tevari does not use raw verse numbers alone. It uses a standardized Bible code format called USFM-style passage IDs.

### Passage ID pattern

```javascript
const usfmPassagePattern = /^[A-Z0-9]{3,5}\.?\d+(?:\.\d+)?(?:-\d+(?:\.\d+)?)?$/;
```

A more readable version of the common pattern is:

```text
BOOK.CHAPTER.VERSE
BOOK.CHAPTER.VERSE-ENDVERSE
```

### Examples

- `MRK.5.25-34`
- `PSA.23.1`
- `PHP.4.6-7`
- `JHN.11.32-36`

These are used to fetch the passage from YouVersion.

## How a human-readable reference becomes a Bible code

In `backend/functions/src/index.js`, the function `passageIDFromText()` turns inputs like `Mark 5:25–34` into a valid passage ID like `MRK.5.25-34`.

```javascript
function passageIDFromText(value) {
  if (typeof value !== "string") return null;

  for (const [bookName, bookCode] of Object.entries(storyBookCodes)) {
    const namePattern = bookName.replace(/ /g, "\\s+");
    const reference = new RegExp(
      `\\b${namePattern}\\s+(\\d+)(?:\\s*[:.]\\s*(\\d+))?(?:\\s*[-–—]\\s*(?:(\\d+)\\s*[:.]\\s*)?(\\d+))?`,
      "i"
    ).exec(value);
    if (!reference) continue;
    const [, chapter, verse, endChapter, endVerse] = reference;
    const start = verse ? `${bookCode}.${chapter}.${verse}` : `${bookCode}.${chapter}`;
    const end = endVerse ? `-${endChapter ? `${endChapter}.` : ""}${endVerse}` : "";
    return validatedStoryPassageID(`${start}${end}`);
  }

  const normalized = value.toUpperCase()
    .replace(/[–—]/g, "-")
    .replace(/:/g, ".")
    .replace(/\b([A-Z0-9]{3,5})\s+(\d+)/g, "$1.$2");
  const match = normalized.match(/[A-Z0-9]{3,5}\.\d+(?:\.\d+)?(?:-\d+(?:\.\d+)?)?/);
  if (match) return validatedStoryPassageID(match[0]);
  return null;
}
```

This means the app can accept:

- `Mark 5:25-34`
- `Mark 5.25-34`
- `MRK.5.25-34`

and normalize them all to a valid YouVersion passage ID.

## How the app calls it from Swift

The Swift app wraps the backend calls in `Tevari/TevariAPI.swift`.

```swift
static func scripturePassage(
    bibleID: Int,
    passageID: String
) async throws -> TevariScripturePassage {
    try await request(
        path: "scripturePassage",
        body: ["bibleID": bibleID, "passageID": passageID]
    )
}
```

This request is made to the Tevari backend, which then calls YouVersion using the app key.

## Where the actual backend endpoint is defined

There is also a dedicated endpoint `scripturePassage` in the backend.

```javascript
export const scripturePassage = onRequest(
  {
    region: "us-central1",
    cors: false,
    secrets: [youVersionAppKey]
  },
  async (request, response) => {
    if (request.method !== "POST") return sendError(response, 405, "method_not_allowed", "Use POST.");
    const user = await requireFirebaseUser(request, response);
    if (!user) return;

    const bibleID = request.body?.bibleID;
    const passageID = request.body?.passageID;
    if (!Number.isInteger(bibleID) || bibleID <= 0 || typeof passageID !== "string" || !usfmPassagePattern.test(passageID)) {
      return sendError(response, 400, "invalid_request", "Bible ID or passage ID is invalid.");
    }

    try {
      const headers = { "X-YVP-App-Key": youVersionAppKey.value(), Accept: "application/json" };
      const [passageResponse, bibleResponse] = await Promise.all([
        fetch(`https://api.youversion.com/v1/bibles/${bibleID}/passages/${encodeURIComponent(passageID)}`, { headers }),
        fetch(`https://api.youversion.com/v1/bibles/${bibleID}`, { headers })
      ]);

      if (!passageResponse.ok || !bibleResponse.ok) {
        console.error("YouVersion request failed", { passageStatus: passageResponse.status, bibleStatus: bibleResponse.status });
        return sendError(response, 502, "scripture_service_unavailable", "Tevari could not retrieve this passage right now.");
      }

      const [passage, bible] = await Promise.all([passageResponse.json(), bibleResponse.json()]);
      response.status(200).json({
        passage: { id: passage.id, reference: passage.reference, content: passage.content },
        bible: {
          id: bible.id,
          title: bible.title,
          abbreviation: bible.abbreviation,
          copyright: bible.copyright,
          info: bible.info,
          publisherURL: bible.publisher_url,
          deepLink: bible.youversion_deep_link
        }
      });
    } catch (error) {
      console.error("Scripture request failed", { message: error instanceof Error ? error.message : "unknown" });
      sendError(response, 502, "scripture_service_unavailable", "Tevari could not retrieve this passage right now.");
    }
  }
);
```

## How scriptures are selected in app flow

The backend uses AI responses to decide a passage ID, then retrieves the actual content from YouVersion.

Example flow:

1. User enters a prayer, prompt, or image question
2. Gloo AI identifies likely biblical passage(s)
3. Tevari validates or repairs the passage ID
4. Backend calls `licensedScripture(passsageID)`
5. YouVersion returns the actual scriptural text and metadata
6. App displays the result as licensed scripture

Examples from the code:

- Prayer: `fallbackPassageID(history)`
- Story: `resolveStoryPassageID()`
- Parallel: `resolveParallelPassageIDs()`
- Faith Lens: `resolveFaithLensPassageID()`

## Examples of passage selection logic

### Prayer fallback

```javascript
function fallbackPassageID(history) {
  const prayer = history.map((item) => item.content).join(" ").toLowerCase();
  if (/health|heal|healing|sick|illness|body|pain/.test(prayer)) return "JAS.5.15";
  if (/anxious|anxiety|worry|worried|fear|afraid/.test(prayer)) return "PHP.4.6-7";
  if (/grief|grieve|mourning|loss|lost|sad/.test(prayer)) return "PSA.34.18";
  return "PSA.23.1";
}
```

### Story fallback

```javascript
function fallbackStoryPassageID(prompt) {
  const context = prompt.toLowerCase();
  if (/samson.{0,50}delilah|delilah.{0,50}samson/.test(context)) return "JDG.16.4-21";
  if (/cain|abel|able/.test(context)) return "GEN.4.7";
  if (/issue of blood|woman.{0,40}(?:blood|bleed|hemorrhag)|(?:blood|bleed|hemorrhag).{0,40}woman/.test(context)) return "MRK.5.25-34";
  return null;
}
```

## Main takeaway

Tevari’s implementation is a clean pattern:

- AI chooses a Bible reference or passage candidate
- Tevari normalizes/validates that reference into a USFM-style ID
- The backend calls the YouVersion API using the app key
- The returned text is displayed as licensed Scripture

This ensures the app can show real Bible text without generating it locally or pretending it is AI-authored scripture.

Tevari uses YouVersion as the source of truth for Scripture, with a locked NIV11 translation (`bibleID = 111`). It stores the YouVersion app key in Firebase secret configuration, validates or repairs passage IDs, and calls the YouVersion API to fetch the actual verse text.
